## Project Overview

The pulse-mini-seed project is a mini-monorepo containing 3 microservices
that simulate a small part of the HelloIT Pulse production system.
The 3 services are:

- auth-gateway : handles authentication via JWT.
- tickets-api : manages tickets (create, read, list).
- notifications-worker : sends notifications via Slack.

This monorepo uses npm workspaces. The root package.json declares all
services as workspaces and exposes scripts to run them in parallel using
concurrently.

The project is owned by the HelloIT Pulse team. The current sprint focus
is on adding the planning module. The team consists of 6 developers and
1 tech lead. Sprints are 2 weeks long. The product manager is Sophie, the
tech lead is Marc.

## Tech Stack

The project uses Node.js v20 LTS. Each service has its own package.json
with its own dependencies. The services use ES modules (type: module
declared in each package.json).

- auth-gateway uses Fastify v4 for the HTTP server, and the jsonwebtoken
  library for JWT signing and verification.
- tickets-api uses Express v4 for the HTTP server. No database is wired
  up yet — tickets are stored in memory in a JavaScript Map.
- notifications-worker uses Express v4 for the API and a setInterval
  timer for the background worker.

The repo uses concurrently (declared as a root devDependency) to run all
services in parallel via `npm run dev`.

## API Endpoints

### auth-gateway (port 4000)

- POST /auth/login — body { username, password }, returns { token }.
- GET /auth/verify — header Authorization: Bearer <token>, returns
  { ok, payload }.

### tickets-api (port 4001)

- POST /v1/tickets — body { title, body, priority, reporter }, returns
  the created ticket with id and createdAt fields.
- GET /v1/tickets/:id — returns a single ticket or 404 if not found.
- GET /v1/tickets — returns all tickets as a JSON array.

### notifications-worker (port 4002)

- POST /v1/notifications — body { channel, message, recipient }, queues
  a notification and returns { queued: true }.

## How to Run

To install dependencies : `npm install`
To run all services in parallel : `npm run dev`
To run a single service : `npm run dev:auth`, `npm run dev:tickets` or
`npm run dev:notif`
To run all tests : `npm test`

## Migrations

Migrations are stored in the migrations/ folder. They follow the Flyway
naming convention : VNNN__description.sql.

- V001__init_schema.sql : creates the initial users and tickets tables.
- V002__add_priority_column.sql : adds a priority index for fast lookups.
- V003__drop_legacy_status.sql : removes the legacy_status column from
  the tickets table.
